# MicroDuck 水面游泳任务设计

日期：2026-11-05（Asia/Shanghai）。状态：设计完成，尚未实现任务或开展游泳训练。
用户确认的第一版目标：身体浮在水面，双脚划水，跟随前进速度与转向角速度指令。
本文件规定第一版实现和验收契约；后续实测调整须记录配置及依据。

## 1. 任务边界与已有基础

- 指令为 `c = (v_forward, yaw_rate)`，侧向目标速度为零；先学前进、启停、左右转与原地转向。
- 使用原生粒子流体与双向刚体耦合，推进只能来自机器人关节动作和流体反作用。
- 身体可以接触水，脚可以出水恢复；碰池底、蹬池壁、出水跳跃不计作游泳。
- 入水、上岸、潜泳、倒游和陆水统一策略留到后续任务，第一版从水中稳定姿态出生。

当前源码基础：

| 项目 | 已有状态 | 本任务需要补充 |
| --- | --- | --- |
| `scenes.py` | 原生 `pool`、流体注册、水粒子分世界重置 | 水面/吃水观测和游泳边界 |
| 池几何 | 长 2 m、宽 0.4 m、水深 0.30 m、墙高 0.40 m | 转向前核验机器人扫掠范围 |
| 流体 | 间距 0.02 m、密度 5000、体积模量 200 kPa、黏度 0.001 Pa·s | 漂浮与划水推进标定 |
| `env.py` | 50 Hz 控制、14 维饱和 PD、统一物理步进 | 独立游泳奖励、终止及观测 |
| `policy.py` | 固定 61 维当前观测及 10×48 历史的陆地网络 | 独立游泳历史网络 |

以上为本次设计时源码值，交接文档中的早期池尺寸已经过时。
密度 5000 是现有实验介质，不能称为真实水；本设计不自动修改它。

2026-11-05 密度实测补充：用户明确吃水目标按整只鸭子（含头脚）的高度，约2/3水下、1/3水上。
单环境、完整碰撞资产、共享HOME关节PD、根部自由且无额外浮力/平衡辅助，800 kg/m³ 连续12秒测试的
最后2秒平均水下高度为65.95%，嘴净空4.22 cm、脚离池底8.36 cm，0池底/壁接触。
因此将800作为该目标的初始候选；生产默认仍为5000。该结果不代表已通过划水推进或策略验收。
初始roll=5°另测4秒，末段倾角约11°、水下高度约63.5%，未自动回正；密度选择不能替代主动稳姿。
测量方法、原始状态及侧视图见 `.validation/microduck_pool_density_20261105/REPORT.md`。
按当前几何，每世界约 30000 个流体粒子，16 世界约 480000 粒，不能照搬平地 1024 环境。

## 2. 先完成物理可行性标定

训练前完成以下检查，产物保存为独立标定报告，不能用 PPO 高回报替代物理验证。

1. **碰撞与排水**：使用完整身体碰撞模型，核验躯干、头部和双脚实际参与流体耦合。
   不能直接沿用仅足部有效碰撞的行走资产；完整碰撞与开启自碰撞分开配置。
   核对质量、碰撞体尺度、足部厚度与粒子间距，避免薄脚漏耦合或重复碰撞体重复排水。
2. **漂浮**：估计 `rho * V_displaced >= mass` 是否可能满足，并用自由漂浮实测确认。
   对若干温和屈腿姿态，保持关节 PD、根部自由，静置 10–20 s，记录吃水、倾角和固体接触。
   不能靠改机器人质量或叠加外部浮力掩盖几何/耦合问题。
3. **确定参考**：选出嘴部出水、脚不碰底的可行姿态 `q_swim`，测得根部相对水面高度 `h_ref`。
   `q_swim` 和 `h_ref` 属于标定结果，不能直接使用陆地 HOME 高度或虚构一个数值。
   同密度课程内冻结参考，不能每步跟着沉降更新；改变介质密度时重新标定。
4. **推进**：在无墙/底接触的中心区域，用幅度受限的关节划动测量净位移与速度。
   对照固定姿态与前后反向划动，核验平均推进方向可改变，并在停止划动后逐步减速。
   脚部流体接触数量不能冒充推进力，更不能把未填充的接触力缓冲当成测力。
5. **数值与容量**：候选采用 2.5 ms×8、非线性 5/线性 35、关节 primal=4，控制周期仍为 20 ms。
   这是待测候选，不是已验证的流体最优设置；从单世界逐级测到目标并行数。
   保留非有限状态、异常速度及接触容量保护，记录实际加载的原生库与物理配置。

标定通过条件：至少一个可行姿态能连续漂浮 10 s，嘴部通常高于水面 2 cm，倾角小于 20°，
没有池底/池壁支撑、非有限状态或容量溢出；受限划动存在可重复的有符号推进。
若在目标密度 1000 下无法漂浮，应先决定浮体/防水壳体设计，再训练对应模型。
密度从 5000 改成 1000 会改变承载能力与动力学，不能把它当作保证成功的普通随机化。

## 3. 状态、动作与观测

### 3.1 状态定义

- `v_x, v_y`：全身质心的世界水平速度，旋转到机器人仅含 yaw 的水平坐标系。
  不能把俯仰造成的竖直运动投影成前进；角速度补偿与 COM/link-origin 区别沿用现有约定。
- `omega_z`：绕世界竖直轴的角速度，不用倾斜身体坐标系的 z 分量替代。
- `z_water`：局部自由水面估计；`h = z_root - z_water`，误差 `e_h = h - h_ref`。
- `h_mouth`：嘴部标记点相对局部水面的高度；双脚深度以实际脚几何采样点定义。
- `theta`：身体 up 与世界 up 的夹角，`v_z, omega_x, omega_y` 均使用世界坐标。
- `hard_contact`：本控制步所有物理子步中，机器人任意碰撞体与池底/池壁真实接触的并集。
  通过 shape/body 映射与实际 gap 排除预测接触，不把机器人—水接触归入其中。

第一版水面查询采用按世界分组的水平柱栅格：柱宽约两倍粒子间距，取连续水柱上层高度，
对邻近有效柱作中位数和 0.1 s 时间滤波；孤立飞溅粒子与机器人代理粒子不参与。
连续水柱需与主要水体连通，支持不足返回无效标记，不得返回 NaN。
静水标定验证误差应小于 1 cm；细节与代价必须实测，不能直接以所有粒子的最大 z 当水面。
初期静水可用标定水位作明确记录的近似；启用波浪课程前必须通过局部水面验证。
连续 0.2 s 查询无效视作仿真/观测故障，保存诊断并停止该实验，不让策略利用缺测。

### 3.2 动作与网络

保留 14 维关节目标偏移、原关节顺序及 PD：`KP=2, KD=0.053, effort_limit=0.96`。
目标为 `q_target = q_swim + 0.5 * clamp(action, -1, 1)`，并裁至有效关节目标范围。
目标角裁剪不等于强制修改真实关节状态；实际越限仍记录并受惩罚。
头颈参考使用标定的温和姿态，不新增外部姿态平衡力矩。

首版采用仿真可观测的 61 维 Actor 当前帧：

| 内容 | 维度 |
| --- | ---: |
| 身体角速度、投影重力 | 3+3 |
| 相对 `q_swim` 关节位置、关节速度、上一动作 | 14+14+14 |
| yaw 水平坐标系的全身 COM 速度 | 3 |
| 当前前进/转向指令 | 2 |
| 根部相对水面高度、嘴部净空、左右脚浸没深度 | 1+1+2 |
| 身体前/后/左/右水平射线到池壁的距离 | 4 |

合计 `48+3+2+4+4=61` 维。
水面无效时使用最后有效值并保留诊断；达到上述故障时限即退出，不能静默长期填零。
墙距需限制到传感范围，并使用机器人朝向定义射线；不暴露不可解释的世界轴墙序号。
Critic 可另加局部流速、身体浸没比例、固体接触、动力学参数及课程状态。
Actor 含仿真真实速度/水面信息，因此第一版是仿真策略，真机需要传感器或估计器映射。

使用过去 20 帧、每帧 61 维、共 0.4 s 历史，编码 `1220→128→64`，Actor/Critic 各自编码。
MLP 初值为 `256/256/128`；历史不含当前帧，按最近到最远排列。
每控制步只推进一次缓存，局部 reset 只重建选中世界历史；历史复用当前帧归一化统计量。
虽然当前维度也为 61，语义已经不同，不能加载陆地观测归一化、镜像映射或历史网络。

## 4. 奖励函数

### 4.1 总式与有效游泳门控

所有普通奖励都是每秒奖励率，控制步结算一次；失败事件只结算一次：

```text
r_step = dt * [G * (4*r_v + 2*r_yaw) - sum(w_i * p_i)] - 3*failure_event
dt = 0.02 s
r_v   = exp(-((v_x - c_v) / sigma_v)^2)
r_yaw = exp(-((omega_z - c_yaw) / 0.20)^2)
sigma_v = max(0.025 m/s, 0.25*abs(c_v))
```

`G` 只在本步没有硬接触、躯干实际与主水体有交叠、嘴部高于局部水面时为 1，否则为 0。
用固定躯干体积采样点与流体邻域共同确认入水，不只比较根部高度。
从稳定水中出生，避免初始全零门控形成不必要探索障碍。
头部轻微入水时仍有负向净空信号；脚不要求始终浸没，允许自然出水恢复。
失败步屏蔽普通正奖励并加事件惩罚；同一步多个失败原因只扣一次，日志保留各原因。

### 4.2 惩罚定义与初始权重

以下 `mean` 均为单个环境内部均值；`clip01(x)=clamp(x,0,1)`。
姿态允许小范围自然运动，避免用强刚性姿势项压制划水。

| 项 | 非负惩罚定义 | 权重 |
| --- | --- | ---: |
| 侧漂 | `clip01((v_y/0.08)^2)` | 0.30 |
| 倾斜 | `clip01((max(theta-10deg,0)/25deg)^2)` | 0.40 |
| 吃水偏差 | `clip01((max(abs(e_h)-0.015,0)/0.04)^2)` | 0.40 |
| 嘴部净空不足 | `clip01((max(0.02-h_mouth,0)/0.03)^2)` | 0.80 |
| 竖直振荡 | `clip01((v_z/0.15)^2)` | 0.15 |
| 横滚/俯仰角速度 | `clip01((omega_x^2+omega_y^2)/2^2)` | 0.10 |
| 动作变化 | `mean((a_t-a_prev)^2)`，动作已裁到 ±1 | 0.03 |
| 力矩 | 子步平均 `mean((tau/0.96)^2)` | 0.02 |
| 机械功率 | 子步平均 `mean(abs(tau*q_dot))/2 W`，封顶 1 | 0.02 |
| 关节软限位 | 距合法中点超过半量程的 90% 后，余下 10% 归一化平方、均值封顶 1 | 0.20 |
| 头颈偏移 | 头颈四关节 `mean(((q-q_swim)/0.5)^2)`，封顶 1 | 0.05 |

力矩和功率需要在所有物理子步累计，不能只拿 `advance_physics()` 返回的末子步值代表整步。
倾斜使用 10° 死区，吃水使用 1.5 cm 死区；对粒子尺度噪声不做毫米级追踪。
转弯时允许侧漂：将侧漂项乘 `max(0.3, 1-abs(c_yaw)/0.6)`，以免压制正常转弯。
首版不添加生存正奖励、陆地足高/腾空/脚滑奖励，也不惩罚水中身体接触。

### 4.3 防止原地摆腿与奖励冲突

- 不给关节摆幅、划水次数、左右交替或水接触粒子数直接加分；这些不证明推进。
- 不强制某种固定相位，允许策略探索交替/同步划水及差速转向。
- 正向速度跟踪有符号，转向跟踪同样有符号；不能用速度模长替代。
- 零速指令仍保留速度/角速度跟踪，可在水流扰动下划脚维持位置，不强制动作归零。
- 不按出生朝向奖励直行，除非把目标航向及误差明确纳入观测。

例如指令 `0.05 m/s, 0 rad/s`：原地不动的前进项奖励率约 `4*exp(-4)=0.073`，
达到目标则为 4，差约 3.93；不能使用过宽核，让静止也拿到接近满分。
在理想姿态下，静止与正确前进都能拿到 yaw 项 2，这不影响上述推进收益差。
预训练前用标定划动估计动作/功率成本，确保总成本增量远小于 3.93，例如不超过 0.5/s。

若确实出现探索困难，先检查推进物理、噪声幅度、出生和成本竞争，再引入短期划水塑形。
可选塑形只能在有效入水且实际有符号速度达到指令的 30% 后开启，上限 0.2/s，
并在进入启停课程时归零；首版默认关闭，不将它作为游泳成功依据。

## 5. 终止、池边与重置

### 5.1 失败终止

- 任意机器人部位真实接触池底或池壁：立即失败；记录子步接触，禁止先蹬墙再采样速度得分。
- 倾角大于 65° 连续 0.2 s；嘴部低于水面 2 cm 连续 0.3 s。
- 躯干完全离开水体连续 0.3 s，或吃水偏差大于 8 cm 连续 0.5 s。
- 真实关节显著越限等沿用现有保护；数值爆炸/容量溢出属于实验故障，保存诊断并停止，
  不把大量异常帧简单 reset 后继续训练，也不将 NaN 转成正常奖励。

连续时间计数器按物理/控制时间累计，不能误用环境总样本数。
较宽的首版倾角/吃水失败阈值须在标定后确认可达，不能接受不可生存的出生姿态。

### 5.2 池边属于任务规划约束

当前窄池不适合持续任意指令。安全区应按完整碰撞几何的扫掠半径内缩，
初始至少保留 8 cm 余量；若不存在安全转向空间，先加宽池，不能用穿墙解决。
加宽池会线性增加流体粒子，必须重新测量吞吐和耦合稳定性。

指令从安全姿态开始，使用 0.1 s 平滑坡道；坡道中的实际指令同时用于观测和奖励。
定时每 1–2 s 重采样，并基于墙距、当前速度、标定停止距离筛掉不可完成的指令。
近前壁时先下发零速；完成制动后，再下发空间允许的转向。
训练和评估都记录此指令调度器，不能把安全调度描述成策略自主导航能力。

普通阶段 episode 上限 6 s；到达安全区边缘视为失败并扣事件分，防止主动越界逃避跟踪。
仅真正时间上限属于截断，可 bootstrap；物理失败和任务越界均为终止，不 bootstrap。
截断必须使用 reset 前 terminal observation 的价值；不能拿 reset 后新水池状态的价值替代。
实现需核对 RSL-RL 2.3 的 timeout 路径，并在任务适配器中显式处理终态价值。
边界事件同样计入成功率分母，并按指令/出生分层报告；不能删除边缘样本抬高成功率。

### 5.3 重置

从通过标定的水中姿态出发，初期根部位置 ±1 cm、姿态 ±5°、关节 ±0.05 rad。
不从水面上方掉落出生，不使用陆地站起课程。
水粒子和机器人同时按世界重置；清空动作、PD 历史、浸没计时器和策略历史。
可预先生成每种物理配置的静水初态并在 reset 恢复，初态不得携带人为定向水流。
恢复后静置约 0.3 s；此阶段不计 PPO 转移、不发漂浮奖励，状态更新完成后填充历史。
必须检验静置是否显著改变浮姿，必要时从完整耦合静置状态恢复，而不是反复产生入水瞬态。
局部 reset 的静置不能让其他环境额外步进；通过世界隔离或离线缓存解决，不在全局循环偷跑子步。

## 6. 训练课程与升级门槛

采用同一套有界奖励；逐阶段扩大指令/初态/随机化范围，不反复重构奖励目标。
PPO 初值、优化器和归一化从头建立，不继承陆地 optimizer 或 StandUp/Velocity 教师 BC。

| 阶段 | 指令/变化 | 升级条件 |
| --- | --- | --- |
| A 漂浮稳定 | 全部零指令，4 s 回合，固定介质与静水 | 稳定漂浮成功率 ≥95% |
| B 低速直游 | 80% 为 0.04–0.08 m/s，20% 零速；yaw=0 | 运动组成功率 ≥80%，静止组 ≥90% |
| C 提速与启停 | 0.04–0.15 m/s，30% 零速，显式运动→停止片段 | 各速度档 ≥80%，停止成功率 ≥90% |
| D 转向 | 速度上限先降至 0.08，yaw 扩至 ±0.3，再逐级 ±0.6 rad/s | 左/右/直行各组 ≥80% |
| E 鲁棒性 | 固定基准上逐项加入初态、延迟、流速和材料扰动 | 未见条件下各组 ≥80%，基准不退化 |

阶段 A 是建立漂浮姿态，不把长期原地站稳当成阶段 B 成功。
阶段 C 每次速度上限增加 0.025 m/s；阶段 D 的 yaw 上限每次增加 0.1 rad/s。
最终 0.15 m/s、0.6 rad/s 是首轮目标范围，未经实验不保证该机器人能达到。

每次升级使用独立、均值动作、冻结归一化的评估，至少每组 50 回合；
满足连续三次评估才升级。训练窗口不足不能升级，零速/简单组不能冲抵高速或转向失败。
失败率超过 30% 的连续两次评估回退一个档，课程窗口/档位随 checkpoint 保存。
每档保留至少 20% 前一档简单样本，避免灾难性遗忘。

阶段 E 按项逐步开启，先测单项，再组合：

- 出生姿态扩大至 ±10°，关节偏差 ±0.1 rad；动作延迟 0–2 控制步、观测噪声缓慢增加。
- 质量、PD 增益各 ±10%，每回合固定；需显式实现并在元数据记录，不能假定现有事件已覆盖。
- 流体黏度取标称值的 0.5–2 倍，密度先只在已通过漂浮标定的标称值附近 ±5%。
- 水深 ±2 cm 仍必须保持脚不碰底；局部流速 0–0.03 m/s，静水控制组占至少 20%。
- 水流由经过验证的物理初态/边界驱动生成，不通过每步强改粒子速度伪造流体响应。
- 流体参数若需重建模型，则使用固定参数世界组/分批实验，不把构建期参数假装成 episode 随机化。

目标若是真实水，另开 5000→4000→3000→2000→1000 的介质适应实验，
每档重新漂浮标定和验收；任何一档不可浮则停在模型设计问题，不能承诺靠课程解决。

## 7. PPO、算力与检查点

| 参数 | 第一版建议 |
| --- | --- |
| 算法 | 项目已有 RSL-RL PPO，独立游泳 Actor/Critic |
| 控制频率 | 50 Hz |
| 环境数 | 物理短测 1→2→4，训练候选 8→16，按显存/吞吐测量决定 |
| rollout | 128 步，即每环境 2.56 s；8 环境批量 1024 |
| minibatch / epoch | 4 / 5 |
| learning rate | 3e-4，adaptive，desired KL=0.01 |
| gamma / lambda | 0.995 / 0.95 |
| clip / grad norm | 0.2 / 1.0 |
| 初始动作标准差 | 0.3，动作空间归一化为 ±1 |
| entropy | 0.005，进入阶段 D 后可降到 0.001，按探索统计决定 |
| 保存 / 评估 | 每 100 次更新保存；每 200 次更新评估 |

正式训练前先做 4 环境×10 次更新的 PPO 链路短测及保存/恢复/回放。
检查逐项 reward、总 reward、梯度、Adam、归一化、动作饱和率与 reset 原因均有限。
初始正式预算可设 8 环境×128 步×5000 更新，约 512 万转移；这只是实验预算，不是收敛承诺。
以独立评估升级课程；若预算耗尽仍未通过，报告失败模式与证据，不直接无限加轮数。
不占用或停止已有健康训练；并行数由当时 GPU 余量决定。

独立 checkpoint 契约建议为 `surface_swim_v1`，保存完整任务配置、资产/源码指纹、
流体/物理参数、观测语义、网络/优化器/归一化、课程档位与窗口、指令采样规则及种子。
阶段切换仍是同一任务续训；改变观测语义、资产或动力学需显式迁移并建立新实验。
不声称普通 checkpoint 恢复了精确粒子状态和 RNG；新建世界后从有效静水状态重新开始。

## 8. 独立验收

使用均值动作、冻结网络与归一化，保留物理流体交互；至少 3 个 seed，每组每 seed 50 回合。
评估样本和课程升级样本分开；静水基准与扰动测试分开报告。

| 组别 | 指令 | 核心门槛 |
| --- | --- | --- |
| 漂浮 | 0, 0 | 4 s 无失败，水平速度 RMS <0.03 m/s，yaw RMS <0.15 rad/s |
| 直游 | 0.05 / 0.10 / 0.15 m/s，yaw=0 | 稳态速度 MAE ≤max(0.02,25%指令) m/s |
| 直游偏航 | 同上 | yaw MAE <0.15 rad/s；有符号净转角 <15°/4 s |
| 左右转弯 | 0.05 m/s，yaw=±0.3 / ±0.6 | yaw MAE <0.15 rad/s，左右分开统计 |
| 原地转向 | 0 m/s，yaw=±0.3 | yaw MAE <0.15 rad/s，水平速度 RMS <0.04 m/s |
| 启停 | 0→0.10→0 | 起步 1.5 s 内进入速度容差，停止 1 s 内低于 0.03 m/s |
| 鲁棒性 | 同指令分组加随机化/水流 | 各组成功率 ≥80%，静水基准保持达标 |

直游与转向稳态误差去掉指令切换后的前 1 s，失败率仍覆盖完整轨迹。
长距离直游先验证安全距离；池长不足时扩大测试池或缩短规定轨迹并明确报告，
不能将多次 reset 的位移拼成一次连续游泳，也不能只统计存活片段的速度误差。
静水中另报告每段沿固定指令初始朝向的净位移，防止往返摆动仅靠瞬时速度得分。

所有成功回合还必须：无池底/池壁接触，倾角 95 分位 <25°，嘴部净空中位数 ≥2 cm，
嘴部出水时间占比 ≥95%。同时报告失败率、固体接触次数、吃水误差、能耗、
左右脚水下行程、动作饱和率与可视视频；脚部轨迹用于行为诊断，不作为强制交替验收。
对启停、弯游和原地转向必须分别达标，不能只用总回报或一段好看的视频宣布学会游泳。

## 9. 实现接线与最小验证

建议参照独立 `jump.py` 的任务隔离方式新增游泳入口，而不是修改官方陆地任务语义。
环境物理/材料继续集中在 `env.py` 和 `scenes.py`；任务 JSON 只放奖励、指令、课程与 PPO，
不再复制一份环境默认值。完整配置在运行时解析并随 checkpoint 保存。

推荐接线顺序：

1. 完整资产与水中 spawn、物理标定脚本和静水初态缓存。
2. 游泳传感器：水面、全身 COM、嘴/脚深度、池底/墙子步接触并集及边界距离。
3. 独立任务包装器调用共享 `advance_physics()`，实现游泳 observation/reward/done/reset。
   不调用陆地 `step()` 后再叠加游泳奖励，避免提前触发陆地终止、指令和随机推扰。
4. 独立历史网络/归一化、PPO、checkpoint、均值动作回放和固定指令评估。
5. 链路短测通过后，按本文件课程开展正式训练。

需要的定向检查：

- 奖励排序：正确速度优于静止，正确转向优于反向；超速、侧漂、沉底和蹬墙不会提高回报。
- 运动学：水平 COM 与倾斜身体速度投影区别明确，四元数顺序正确。
- 多世界 N=1/2/5：状态与 reward 无跨世界广播，reset 不改其他世界的刚体/水/历史。
- 子步碰壁后即使控制步末已分离，也必须失败；水接触不能误记为池底支撑。
- 终止/截断、一次性失败惩罚、terminal observation 价值与自动 reset 次序正确。
- 相同轨迹用不同控制步长结算，奖励率/时间门槛基本一致，事件惩罚不重复乘 dt。
- 历史首帧、重复读取、局部 reset、训练恢复与回放命令保持契约一致。
- CPU 公式检查、真实 SynReal 物理短测、PPO 链路和长期技能验收分别记录结果。

当前仅完成上述设计；尚无游泳训练入口、游泳 checkpoint 或行为收敛证据。
